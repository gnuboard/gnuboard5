# 그누보드 5.6.44 업데이트 안내

- 배포일: 2026-10-30
- 패치 기준: 5.6.43
- DB 업그레이드: 필수 (`20261029_001_kcp_payment_api`, `20261029_003_pg_approval_log`)
- 삭제 대상 파일: `adm/phpinfo.php`

## 변경 내용

- KCP REST API 연동 선택을 추가했다. PC·모바일 결제 승인, 전체·부분취소, 모바일 거래등록, 에스크로 처리 및 현금영수증 개별 발급·취소에 적용한다. 기존 KCP 결제 모듈 방식은 기본값으로 유지된다.
- 쇼핑몰 결제 설정을 PG별 탭으로 정리하고 이니시스 기존 방식과 PRO 설정을 구분했다.
- KCP, 이니시스, 토스페이먼츠, XPay, 나이스페이의 승인 카드정보를 공통 기록하고 관리자 주문 상세에서 펼쳐 볼 수 있게 했다. 기록 기능 적용 전 주문은 안내 문구를 표시하며, 기록 부재가 결제 실패를 의미하지 않는다.
- 이니시스 인증·승인 응답을 키 이름으로 처리하고 필수 값 검증을 보완했다. 추가 응답 필드는 유연하게 처리한다.
- 서버에서 exec가 차단되었을 때 KCP 기본 모듈을 사용할 수 없음을 명확히 안내하고 경고 반복을 방지했다.
- 관리자 phpinfo 메뉴와 파일을 제거했다.

## 업데이트 순서

1. 소스·DB·data 및 개별 수정 파일을 백업하고 결제와 관리자 작업을 잠시 중지한다.
2. 5.6.43 사용자는 패치 ZIP, 이전 버전 사용자는 전체 파일과 누적 변경을 검토하여 적용한다. config.php, data 및 별도 수정 파일은 보존·병합한다.
3. 기존 `adm/phpinfo.php`를 삭제한다. 패치 ZIP 압축 해제만으로 삭제되지는 않는다.
4. 관리자 DB 업그레이드를 실행한다. DB 계정에 필요한 ALTER·CREATE·INDEX 권한을 확인한다. 두 마이그레이션의 성공을 확인한다.
5. 브라우저 캐시를 갱신하고 쇼핑몰 설정·주문 상세·결제 승인 및 취소를 확인한 뒤 서비스를 재개한다.

기존 상점의 KCP 연동방식은 자동으로 REST로 전환되지 않는다. REST를 사용하려면 해당 상점의 서비스 인증서·개인키를 웹 루트 밖에 설치하고 경로·비밀번호를 서버 설정에 등록한 뒤 쇼핑몰 설정에서 선택한다. PHP cURL·OpenSSL·JSON·iconv 및 TLS 1.2 이상이 필요하다. 설정 및 호스팅 요구사항은 [KCP REST API 안내](kcp-rest-api.md)를 참조한다. 홈페이지 HTTPS 인증서와 별개의 인증서이다.

진행 중인 결제는 연동 설정 변경 전에 완료하거나 PG 내역과 대조한다. 운영 상점 코드와 테스트/운영 인증정보를 혼용하지 않는다. 기능 적용 이전 승인 카드정보를 소급 생성하지 않는다.

## 검증 범위

PHP 8.3·8.4에서 변경 PHP 문법, KCP REST 단위·통신·PC/모바일 일반 주문·개인결제 모의 통합, PG 승인 로그, 이니시스 응답·서명, 주문 접근·필드·호환성, 간편결제 회귀를 검사했다. 격리 DB를 사용하는 현금영수증 회귀 218개를 두 버전에서 통과했다.

PHP 8.4.27 새 설치 환경에서 KCP 기본·REST 각각 PC·실제 모바일 일반 신용카드 주문 1,100원의 승인 및 전체취소를 완료했다. REST는 exec 차단 상태의 실제 API 호출 기록을 확인했다. 다른 결제수단·모든 카드사·에스크로 및 부분취소의 실제 외부 거래를 이번 배포 검증에서 모두 수행한 것은 아니다.
