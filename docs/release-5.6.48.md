# 그누보드 5.6.48 업데이트 안내

재설치 후 남은 로그인 세션으로 발생하는 경고와 KCP REST 모바일 실결제창이 열리지 않는 문제를 수정했습니다.

## 개발자 노트

같은 주소에 사이트를 다시 설치하면 브라우저에는 이전 로그인 정보가 남아 있을 수 있습니다. 새 DB에 그 회원이 없으면 첫 접속부터 PHP 경고가 표시되고 화면 이동이나 로그인 처리까지 방해할 수 있습니다. 이번 버전은 회원을 찾지 못한 로그인 정보를 해제하고 비회원으로 전환해 다시 로그인할 수 있도록 합니다. 회원이 삭제됐는데 예전 로그인 상태가 남아 있는 경우에도 적용됩니다.

KCP REST 방식을 사용하는 쇼핑몰에서는 PC 결제가 정상이어도 모바일 실결제창이 열리지 않을 수 있었습니다. KCP가 거래등록에 성공한 뒤 돌려주는 결제창 주소를 쇼핑몰에서 잘못 거절했기 때문입니다. 이번 패치는 정상 운영 결제창 주소를 허용해 모바일 결제를 이어갈 수 있게 합니다.

## 패치 노트

- 회원 조회 결과가 없으면 회원 정보를 읽기 전에 로그인 세션과 인증 토큰을 해제합니다.
- KCP REST 모바일 거래등록 응답에서 운영 결제창 호스트 rsmpay.kcp.co.kr을 허용합니다. 기존 smpay.kcp.co.kr과 테스트·운영 구분, HTTPS 및 위장 도메인 거부 조건을 유지합니다.
- [KCP 모바일 실결제 거래등록 실패 제보](https://github.com/gnuboard/gnuboard5/issues/398)를 반영했습니다.

4. 관리자 DB 업그레이드에서 이전 버전의 미완료 항목을 확인합니다. 5.6.47의 거래번호 비교 방식 변경을 아직 적용하지 않았다면 해당 마이그레이션을 완료해 주세요.
5. 메인 화면과 로그인, 사용하는 KCP 모바일 결제창을 확인한 뒤 서비스를 재개합니다.

## 검증 범위

PHP 8.3·8.4에서 회원 조회 실패·정상 로그인·차단·탈퇴·인증 만료 회귀 검사를 통과했습니다. 별도 설치본에서 로그인 세션을 유지하고 DB를 재설치하여 경고를 재현한 뒤, 수정 파일 반영 후 경고 없이 비회원으로 전환되고 정상 관리자 로그인이 가능한 것을 확인했습니다.

KCP PC·모바일 및 일반 주문·개인결제 승인 회귀 검사와 모바일 거래등록 처리기 검사를 통과했습니다. 운영 결제창 주소는 모의 응답으로 검사했으며 실제 운영 모바일 결제·취소는 추가 확인이 필요합니다.
