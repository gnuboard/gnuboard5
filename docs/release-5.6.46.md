# 그누보드 5.6.46 업데이트 안내

쇼핑몰 미설치 사이트에서 잔여 쇼핑몰 테이블 때문에 DB 업그레이드가 중단되는 문제를 수정했습니다. 이전 업그레이드가 실패한 사이트는 파일 반영 후 관리자 **환경설정 → DB 업그레이드 → 전체 마이그레이션 실행**을 다시 진행해 주세요.

## 변경 내용

- 쇼핑몰 사용 설정이 없으면 쇼핑몰 SQL을 건너뛰고 공통 DB 변경을 계속 실행합니다. 잔여 쇼핑몰 테이블과 데이터는 수정하지 않습니다.
- 쇼핑몰 사용 설정이 있는 사이트에서 필요한 테이블 또는 컬럼 추가 위치의 기준 컬럼이 없으면 누락 내용을 안내하고 중단합니다. DB 조회 실패를 미설치로 처리하지 않습니다.
- 상태 조회·기존 상태 확인 이력 등록·전체 실행의 문 단위 판정을 통일했습니다. 기존 배포 SQL과 적용 이력의 체크섬은 유지합니다.
- 한 파일에 공통 SQL과 쇼핑몰 SQL이 섞여 있어도 공통 변경은 정상 처리합니다.

**[릴리즈 노트 및 업데이트 안내]**

- 버전: 5.6.46
- 배포일: 2026-11-02
- 패치 기준: 5.6.45
- DB업그레이드: 불필요 (새 DB 변경 없음). 이전 업그레이드 미완료 사이트는 전체 실행 필요
- 삭제 대상 파일: 없음

## 업데이트 순서

1. 현재 파일·DB·data 디렉터리를 백업하고 변경 작업 중 서비스 이용을 일시 중지합니다.
2. 5.6.45 사이트는 패치 ZIP을 반영합니다. 더 오래된 버전은 전체 배포본으로 누적 변경을 반영하며 사용자 수정 사항과 설정을 보존합니다.
3. 이전 DB 업그레이드가 실패했거나 대기 항목이 있으면 관리자 DB 업그레이드에서 전체 마이그레이션을 실행합니다. 기존 상태 확인 이력 등록은 SQL을 실행하지 않으며 실패 이력을 복구하는 버튼이 아닙니다.
4. 비밀번호 찾기 요청 제한 저장소 경고가 사라졌는지, 마이그레이션 상태가 정상인지 확인합니다. PHP 캐시를 사용하는 경우 변경 파일이 반영되도록 캐시를 갱신하고 로그인·게시판·비밀번호 찾기 및 사용 중인 쇼핑몰을 확인한 뒤 서비스를 재개합니다.

쇼핑몰을 사용하는 사이트는 `G5_USE_SHOP` 설정을 실제 설치 상태와 일치시켜야 합니다. 오류 회피를 위해 설정을 끄거나 누락 컬럼을 임의로 추가하지 마세요. 불완전한 구조 오류가 나오면 해당 DB 설정과 테이블을 확인·복구한 후 다시 실행합니다. 이번 변경은 전체 쇼핑몰 스키마를 자동 복원하지 않습니다.

## 검증 범위

공식 5.6.22 설치 코드로 만든 별도 테스트 환경에 후보 파일을 덮어쓰고, PHP 8.3·8.4에서 게시판 전용·잔여 주문 테이블·정상 쇼핑몰·불완전한 주문 테이블의 8개 조합을 검증했습니다. 전체 34개 마이그레이션 이력·체크섬, 재실행 시 추가 적용 0건, 비밀번호 찾기 요청 제한 저장소 준비, DB 설정과 회원 데이터 보존을 확인했습니다. 불완전한 주문 테이블은 오류 안내 후 구조를 복구하여 재실행했습니다. 별도로 실행 조건·신규 설치 이력·조회 실패·연속 컬럼 추가의 회귀 검사를 수행했습니다. 실제 외부 메일 발송이나 PG 결제는 이번 검증에 포함하지 않습니다.

실행 조건과 후설치 동작은 [DB 마이그레이션 안내](database-migrations.md)를 참고해 주세요. PHP 최소 지원 버전 변경과 포인트다모아 기능 변경은 이번 배포에 포함하지 않습니다.
