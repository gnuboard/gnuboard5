# 그누보드(영카트) 5.6.42 배포 안내

변경 기준은 5.6.41입니다.

비밀번호 찾기의 반복 요청과 메일 발송 남용을 줄이고, 모바일 결제의 면세금액 0 및 토스 상품명의 특수문자 처리를 보완합니다. **기존 설치는 파일 반영 후 관리자 DB업그레이드가 필요합니다.**

## 변경 사항

- 비밀번호 찾기 요청에 IP별 한도와 수신자·사이트 전체 메일 발송 한도를 적용합니다. 수신자와 전체 한도는 한 트랜잭션에서 확보하며, 제한된 요청은 기존 복구 링크를 변경하지 않습니다.
- 최고관리자의 환경설정 → 기본환경설정 → 기본 메일 환경 설정에서 요청 제한을 조정하고 기본값으로 복원할 수 있습니다. 외부 서비스나 사이트별 운영 통계 수집 없이 기본 정책으로 동작합니다.
- 잘못된 복구 링크가 정상 링크를 무효화하지 않도록 하고, 정상 링크의 비밀번호 변경과 일회성 소모를 함께 처리합니다. 메일러가 실패를 반환하면 인증값을 조건부 복원하고 해당 수신자의 재시도 대기를 최대 60초로 줄입니다.
- 주문 필드 복원 시 숫자·문자열 0을 보존하고 저장 과정에서 추가된 이스케이프를 한 번만 해제합니다. 모바일 토스의 면세금액 0과 상품명의 따옴표·역슬래시가 유지됩니다.
- PC·모바일 토스 일반 주문과 개인결제의 상품명을 HTML·JavaScript 문맥에 맞게 인코딩합니다.

## 업데이트 방법

1. 파일과 DB를 백업하고 비밀번호 찾기 및 주문·결제 작업을 잠시 중지합니다.
2. 5.6.41 설치본에 전체 소스 또는 `gnuboard5.6.42.patch.zip`을 반영합니다. 이전 버전은 선행 업데이트도 적용하십시오. 사용자 수정 주문서·결제 폼에도 변경 내용을 병합해야 합니다.
3. 최고관리자로 관리자 DB업그레이드에서 `20261008_001_abuse_rate`, `20261008_002_abuse_rate_transaction`, `20261008_003_password_lost_policy`를 순서대로 적용합니다. 제한 저장소는 InnoDB를 사용합니다. DB 준비나 권한 확인에 실패하면 비밀번호 찾기가 제한됩니다.
4. 기본 메일 환경 설정의 비밀번호 찾기 요청 제한을 확인합니다. 기본값은 IP 연속 10회·6초당 1회 회복, 전체 발송 연속 30회·1초당 1회 회복, 수신자 300초당 1회입니다. 회복 간격은 응답을 그 시간만큼 지연시키는 설정이 아닙니다. 공유 IP 사용자는 IP 한도를 함께 사용합니다.
5. 메일에 사용할 사이트 주소 설정과 실제 수신을 확인하고, 정상 요청·반복 요청·기존 복구 링크 사용을 검사합니다. SMTP 수락 이후의 실제 수신 실패는 감지할 수 없으며, 화면은 발송 조건을 설명하는 공통 안내를 표시합니다.
6. 브라우저·CDN 캐시를 갱신하고 사용하는 PC·모바일 결제 경로에서 주문명, 결제금액, 면세금액 및 완료 처리를 확인한 뒤 운영을 재개합니다.

새 설치에는 변경 스키마가 포함됩니다. 기존 설치의 관리자 정책 컬럼이 없거나 비어 있으면 기본 정책을 사용하지만, 제한 저장소와 InnoDB 전환은 필요합니다. 자세한 내용은 [DB 마이그레이션 안내](database-migrations.md)를 확인하십시오.

## 검증과 한계

격리 DB·실제 PHP/HTTP 회귀 검사와 주문 필드 검사를 사용합니다. 모바일 토스 v2 테스트 결제에서 1,500원 승인, 면세금액 0, 따옴표·역슬래시가 포함된 상품명의 DB·PG 일치를 확인했습니다. 모든 PG·기기·결제수단을 실결제 검증한 것은 아닙니다.

이번 제한은 비밀번호 찾기 경로에 적용됩니다. 기본 Kcaptcha의 고정 음원 연결에 따른 자동 판독 문제 자체를 해결하는 변경은 아니며, 가입·다른 메일 경로와 캡차 발급 이전의 유입까지 보호하지 않습니다. 사이트 전체의 시간·일 단위 발송 예산을 보장하지도 않습니다. 기본환경설정에서 지원하는 대체 캡차 사용을 검토하십시오.

포인트다모아 개발 브랜치의 변경은 포함하지 않습니다.
