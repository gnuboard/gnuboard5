# 그누보드 5.6.55 모바일 결제·본인확인 처리 수정 안내

모바일 기기로 PC 화면을 보는 사이트(반응형 테마를 PC 화면으로 고정한 경우, 모바일 사용을 끈 경우, 방문자가 PC 버전을 선택한 경우)에서 일부 결제·본인확인 처리가 어긋나던 문제를 수정했습니다. 이니시스 모바일 결제 결과 통보의 장바구니 복원 기준도 서버 값으로 고정했습니다. 관리자 SMS 주소록과 미완료주문 화면의 오류도 함께 수정했습니다. 새 DB 변경과 삭제 대상 파일은 없으며, 5.6.54 사용자는 패치 파일을 적용할 수 있습니다.

## 개발자 노트

그누보드는 모바일 기기에서 주문하면, 화면을 PC로 보고 있더라도 결제는 모바일용 주문서와 결제창으로 진행합니다. 그런데 일부 결제·본인확인 처리는 기기 대신 지금 보고 있는 화면(PC/모바일)을 기준으로 동작해, 모바일 기기로 PC 화면을 보는 경우 서로 맞지 않았습니다.

그 결과 KG이니시스 PRO 결제에서 결제 버튼을 눌러도 진행되지 않았고, LG U+ 결제가 실패하면 주문서로 돌아오지 못했습니다. 이니시스 모바일 결제에서는 결과 통보로 주문을 만들 때 필요한 장바구니 정보가 저장되지 않아, 결제는 승인됐는데 주문이 생성되지 않을 수 있었습니다. KCP 휴대폰 본인확인을 취소하면 빈 창이 남기도 했습니다.

또한 임시주문 저장 과정에서 장바구니 정보가 요청값 그대로 저장될 수 있었습니다. 이니시스 모바일 결제 결과 통보는 이 값으로 장바구니를 복원했으므로, 다른 장바구니로 주문이 처리될 여지가 있었습니다.

이번 버전부터는 화면 설정과 관계없이 결제를 시작한 주문서에 맞게 처리하고, 결과 통보의 장바구니는 서버가 기록한 값으로만 복원합니다. PC/모바일 화면 구분 방식(G5_IS_MOBILE) 자체는 바뀌지 않습니다.

관리자 화면에서는 두 가지를 고쳤습니다. SMS 휴대폰번호 관리와 문자 보내기의 주소록은 주소에 초성 검색 값이 붙으면 없는 처리 함수를 불러 오류로 멈췄습니다. 화면에서 제공하지 않는 기능이므로 이 값을 무시합니다. 미완료주문 내역에서는 고객이 쓴 배송비 쿠폰의 할인이 항상 0으로 계산되어, 주문합계와 미완료주문을 주문으로 넘길 때 저장되는 결제금액·배송비 할인이 실제와 달랐습니다.

## 패치 노트

- **KG이니시스 PRO 모바일 주문서:** 결제에 필요한 보조 폼을 화면 모드가 아니라 모바일 주문서에서 불러왔는지로 만듭니다(shop/inicis/pro/orderform.1.php, shop/inicis/orderform.1.php, mobile/shop/inicis/orderform.1.php).
- **토스페이먼츠·LG U+ 승인 실패:** 화면 모드와 관계없이 결제를 시작한 화면(개인결제·바로구매 포함)으로 돌려보냅니다. LG U+는 승인 요청 자체가 실패한 경우도 포함합니다(shop/toss/toss_result.php, shop/lg/xpay_result.php).
- **임시주문 장바구니 정보:** 장바구니 주문은 항상 서버 세션의 장바구니 ID를 저장하고, 요청에 담긴 값은 사용하지 않습니다. 개인결제에서는 저장하지 않습니다(shop/ajax.orderdatasave.php).
- **이니시스 모바일 결과 통보:** 장바구니를 임시주문 저장 때 서버가 기록한 장바구니 ID로 복원합니다(mobile/shop/inicis/settle_common.php).
- **KCP 휴대폰 본인확인 취소:** 안내 후 인증 창을 닫습니다(plugin/kcpcert/kcpcert_result.php, plugin/kcpcert/find_kcpcert_result.php).
- **SMS 주소록 초성 검색 값:** 정의되지 않은 처리 함수를 부르지 않고 값을 무시합니다(adm/sms_admin/num_book.php, adm/sms_admin/ajax.sms_write_person.php).
- **미완료주문 배송비 쿠폰:** 배송비 쿠폰 할인을 실제 배송비 기준으로 계산합니다. 미완료주문을 주문으로 넘길 때 배송비 할인과 결제금액도 바르게 저장합니다(adm/shop_admin/inorderform.php, adm/shop_admin/inorderformupdate.php).
- 회귀 검사 tests/inicis_pro_mobile_form.php, tests/screen_mode_channel.php, tests/admin_undefined_refs.php를 추가했습니다.
- 이번 변경에 새 PHP 버전 전용 구문이나 함수는 추가하지 않았습니다.

**[릴리즈 노트 및 업데이트 안내]**

- 버전: 5.6.55
- 배포일: 2026-11-17
- 패치 기준: 5.6.54
- DB업그레이드: 불필요 (새 DB 변경 없음)
- 삭제 대상 파일: 없음

1. 파일과 DB를 백업하고 업데이트 중 사이트 이용을 일시 중지합니다.
2. 5.6.54 사용자는 패치 ZIP을 적용합니다. 2026-11-17 처음 공개한 5.6.55 파일을 이미 적용했다면 같은 날 갱신한 5.6.55 패치 ZIP을 다시 적용합니다(관리자 SMS 주소록·미완료주문 수정 추가). 이전 버전은 전체 배포본을 기준으로 사용자 수정 사항을 병합하고, 기존 data와 DB 설정을 보존합니다. 5.6.51의 삭제 대상 파일 안내도 함께 확인합니다.
3. KG이니시스로 모바일 결제를 받으면서 반응형 테마를 PC 화면으로 고정했거나 모바일 사용을 끈 사이트는, PG 관리자 화면의 모바일 승인 내역과 쇼핑몰 주문 내역을 대조해 주문 없이 승인만 남은 결제가 있는지 확인합니다. 있다면 PG 관리자 화면에서 직접 취소하거나 고객에게 안내합니다.
4. 이전 버전에서 미완료한 DB 업그레이드가 있다면 관리자 DB 업그레이드에서 완료합니다.
5. PHP 코드 캐시와 별도 CDN·페이지 캐시를 사용한다면 갱신합니다. 모바일 기기에서 주문서 작성·결제, 개인결제, 휴대폰 본인확인 화면을 확인한 뒤 서비스를 재개합니다. 문제가 생기면 함께 백업한 이전 코드로 복원합니다.

## 검증 범위

PHP 8.3·8.4·8.5에서 이니시스 PRO 보조 폼 생성 조건, 토스페이먼츠·LG U+ 실패 복귀 주소, 임시주문 장바구니 정보 저장과 결과 통보의 복원 기준, KCP 본인확인 취소 처리, 관리자 SMS 주소록과 미완료주문의 정의되지 않은 함수·변수 참조를 검사했습니다. 수정 전 코드에서는 검사가 실패해 문제가 재현되었습니다.

PHP 8.3·8.4의 신규 설치본에서 모바일·PC 기기와 화면 모드 조합별로 이니시스 PRO 주문서를 열어 보조 폼 생성을 확인했고, 임시주문 저장 결과에 서버 장바구니 ID가 저장되고 요청값은 무시되는 것을 확인했습니다. 관리자로 로그인해 SMS 주소록에 초성 검색 값을 붙여 요청해도 정상 응답하고, 미완료주문 내역의 주문합계에 정률·정액 배송비 쿠폰 할인이 반영되는 것을 확인했습니다. 하위 PHP 버전은 변경 코드에 PHP 5.2보다 새 구문·함수가 없는지 정적으로 검사했습니다.

실제 PG 결제 승인·결과 통보, LG U+ 승인 실패, 미완료주문을 주문으로 넘기는 처리의 실제 실행, KCP 본인확인 모듈 호출, PHP 8.3 미만 실제 실행, 외부 커스텀 주문서 스킨은 이번 검증 범위에 포함하지 않았습니다.
