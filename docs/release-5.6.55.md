# 그누보드 5.6.55 보안 업데이트 안내

관리자 위임 권한, 회원정보 수정, 본인확인·소셜 로그인, 현금영수증, 엑셀 업로드 등에서 제보된 보안 문제 20건(KVE-2026-3246~3256, 3259~3267)을 수정했습니다. 새 DB 변경과 삭제 대상 파일은 없으며, 5.6.54 사용자는 패치 파일을 적용할 수 있습니다.

2026-11-17에 잠시 공개했다가 취소한 5.6.55와는 다른 배포입니다. 그 배포본을 적용했던 사이트는 업데이트 안내 2번을 확인해 주세요.

## 개발자 노트

이번 버전은 외부에서 제보된 보안 문제를 한꺼번에 고친 업데이트입니다. 대부분 로그인한 관리자나 회원이 공격자 페이지를 열었을 때, 또는 일부 권한만 받은 부관리자가 자기 범위를 넘어 다른 자료를 바꿀 수 있었던 문제입니다.

**부관리자(위임 관리자) 권한.** 게시판그룹·게시판·쇼핑몰 분류를 다른 관리자에게 맡긴 사이트에서, 맡은 관리자가 다른 관리자의 그룹이나 게시판 번호를 직접 넣어 관리자를 자신으로 바꾸거나 접근 제한을 풀 수 있었습니다. 또 회원관리 등에서 쓰기(w) 권한만 받은 부관리자가 회원·자료를 삭제할 수 있었습니다. 이제 위임 관리자는 자신이 관리하는 그룹·게시판·분류만 다룰 수 있고, 삭제에는 삭제(d) 권한이 필요합니다.

**회원 화면의 요청 위조.** 로그인한 회원이 공격자 페이지를 열면 회원정보(비밀번호·이메일)가 바뀌거나, 임시저장글·스크랩·위시리스트·배송지가 지워질 수 있었습니다. 회원정보 수정과 이 삭제들은 이제 그 화면에서 발급한 1회용 토큰과 같은 사이트에서 온 요청만 처리합니다. 로그인 뒤 이동할 주소 검사가 특정 형식의 외부 주소를 놓치던 문제(열린 리다이렉트)도 고쳤습니다.

**본인확인·소셜 로그인·PG 통신.** 그누보드가 이니시스·소셜 로그인 제공자 등과 서버끼리 HTTPS로 통신할 때 인증서를 확인하지 않아, 통신 경로를 가로챈 공격자가 응답을 꾸밀 수 있었습니다. 이제 인증서와 호스트 이름을 확인합니다. 소셜 로그인은 로그인을 시작한 세션과 콜백을 묶어 위조된 콜백을 거부하고, 이니시스 간편인증과 기존 방식 KCP 본인확인은 인증 결과를 시작한 세션에서 한 번만 받습니다. 기존 KCP 본인확인 결과 화면에서 받은 값을 그대로 다시 출력하던 문제도 없앴습니다.

**현금영수증.** KCP 외 PG(LG U+·토스페이먼츠·KG이니시스·나이스페이)의 현금영수증 발급에 요청 위조 방지가 없어, 고객이 공격자 페이지를 열면 공격자가 정한 번호로 발급될 수 있었고 동시에 여러 번 요청하면 중복 발급될 수 있었습니다. 이제 KCP와 같은 1회용 토큰·발급 조건 재확인·선점 처리를 거칩니다.

**관리자 엑셀 업로드.** 상품 일괄등록·배송 일괄처리·SMS 휴대폰번호 업로드에서 작은 특수 파일로 서버 메모리·CPU를 오래 붙잡을 수 있었고, 엑셀로 넣은 상품명·배송 정보에 스크립트가 남아 화면에서 실행될 수 있었습니다. 이제 xls·xlsx만 형식을 확인해 읽고 크기·행·열에 상한을 두며, 값은 일반 상품 등록과 같은 방식으로 정리하고 화면에는 글자 그대로 출력합니다.

**그 밖에.** 주문내역 CSV의 수식 주입 방어가 큰따옴표로 우회되던 문제, Browscap 정보를 평문 HTTP로 받아 캐시 파일에 PHP 코드가 들어갈 수 있던 문제, 에디터 이미지 업로드에 누적 제한이 없어 디스크를 채울 수 있던 문제를 고쳤습니다.

보안 수정과 함께, 상품 엑셀 일괄등록에서 `AB2E3`처럼 중간에 "숫자 e 숫자"가 든 상품코드가 `0`이나 다른 숫자로 바뀌어 등록되지 않던 기존 결함도 고쳤습니다.

업데이트 뒤 동작이 바뀌는 부분이 있습니다. 부관리자를 쓰는 사이트, 스킨·테마를 직접 만든 사이트, 기존 방식 KCP 본인확인·Browscap·비회원 에디터 업로드를 쓰는 사이트는 업데이트 안내 3번을 꼭 확인해 주세요.

## 패치 노트

- **KVE-2026-3259 게시판그룹:** 그룹 상세·수정·일괄처리·접근회원 처리에서 그룹의 관리자를 확인합니다. 최고관리자가 아니면 자신이 관리하는 그룹만 처리하고, 그룹 관리자 지정과 그룹 삭제는 최고관리자만 합니다(adm/boardgroup_form.php, boardgroup_form_update.php, boardgroup_list_update.php, boardgroupmember_*.php, adm/admin.lib.php).
- **KVE-2026-3260 게시판:** 게시판 상세·수정·일괄수정·복사에서 게시판이 속한 그룹의 관리자를 확인합니다. 위임 관리자의 "전체적용"은 자신의 그룹 게시판에만 적용되고, 그룹 선택 목록에는 자신의 그룹만 나옵니다(adm/board_form.php, board_form_update.php, board_list_update.php, board_copy*.php).
- **KVE-2026-3261 삭제 권한·GET 삭제:**
  - 회원관리·투표·회원메일·추가배송비·인기검색어·SMS5의 삭제·일괄삭제 처리에 삭제(d) 권한 검사를 추가했습니다. 권한이 없으면 삭제 버튼도 보이지 않습니다.
  - 임시저장글·스크랩·위시리스트·배송지 삭제를 토큰을 실은 POST로 바꿨습니다(js/common.js의 `del_post()`·`g5_post_href()`, js/autosave.js, 기본·basic 테마 스킨).
- **KVE-2026-3246 이동 주소 검사:** `check_url_host()`가 해석할 수 없는 주소, 호스트 없는 절대 주소, 비정상 포트를 거부합니다(lib/common.lib.php).
- **KVE-2026-3252 회원정보 수정:** 같은 사이트 출처 확인, 회원별 1회용 토큰, 비밀번호 재확인 10분 유효를 적용했습니다. 비밀번호를 바꾸면 모든 기기의 자동로그인이 해제됩니다. 최고관리자는 관리자 화면에서 정보를 수정합니다(bbs/register_form.php, register_form_update.php, 회원 스킨).
- **KVE-2026-3253 기존 방식 KCP 본인확인:** 인증 결과를 시작한 세션·용도에 묶어 한 번만 받고, 결과 화면에서 받은 값을 다시 출력하지 않습니다. 관리자 기본환경설정에서 기존 방식을 고르면 api_v2 전환 권고와 운영 사이트 테스트 모드 경고가 나옵니다(plugin/kcpcert/).
- **KVE-2026-3248·3249·3250 서버 간 HTTPS:** 서버 간 HTTPS 통신에 인증서·호스트 이름 검증 공통 함수를 추가해 현금영수증·간편인증·소셜 로그인·네이버페이·이니시스 승인 통신에 적용했습니다(lib/common.lib.php).
  - 3248: 이니시스 현금영수증 응답은 검증·형식 확인 후에만 저장하고 출력할 때 인코딩합니다(shop/inicis/taxsave_result.php).
  - 3249: 이니시스 간편인증 결과 조회 주소를 고정하고, 결과를 시작한 거래에 묶어 한 번만 처리합니다(plugin/inicert/, 새 파일 plugin/inicert/libs/inicert.lib.php).
  - 3250: 소셜 로그인(HybridAuth)의 인증서 검증을 기본으로 켜고, 인가 요청에 1회용 state를 붙여 콜백에서 대조합니다(plugin/social/).
- **KVE-2026-3247 현금영수증:** LG U+·토스페이먼츠·KG이니시스·나이스페이 발급에 1회용 토큰, 출처 확인, 발급 조건 재확인, 처리 중 선점을 적용했습니다. 결과가 불명확하면 "처리 확인 필요"로 남기고 관리자 주문 화면에 표시합니다(새 파일 lib/shop_cash.lib.php, shop/<PG>/taxsave_*.php).
- **KVE-2026-3262~3267 엑셀 업로드:** 상품·배송·SMS 업로드가 형식을 확인한 xls·xlsx만 지정 리더로 읽고, 크기 10MiB·10,000행·필요한 열까지만 읽습니다(새 파일 lib/spreadsheet_upload.lib.php). PHPExcel의 XML 검사 인코딩 우회(3262), Gnumeric 압축 해제(3263), ODS 반복(3264), OLE 섹터 순환(3265), 행 번호(3266), 열 범위(3267)도 라이브러리에서 막았습니다(lib/PHPExcel/).
- **KVE-2026-3256 엑셀 일괄처리 XSS:** 상품 엑셀 등록은 관리자 토큰을 확인하고, 상품명 등은 일반 상품 등록과 같은 정화를 거치며, 위임 관리자는 자신이 관리하는 분류에만 등록합니다. 배송 엑셀의 배송회사·운송장번호는 태그를 지우고 255자로 자릅니다. 상품명·배송 정보는 화면과 배송 안내 메일에 인코딩해 출력합니다(adm/shop_admin/itemexcelupdate.php, orderdeliveryupdate.php, 상품·주문 스킨).
- **KVE-2026-3254 주문내역 CSV:** 셀 단위로 따옴표를 처리해 직렬화하고, 수식으로 시작하는 셀은 `'`를 붙여 중화합니다(adm/shop_admin/orderprintresult.php).
- **KVE-2026-3255 Browscap:** 업데이트를 인증서가 확인된 HTTPS로 받고, 캐시는 `var_export()` 형식으로 만들어 읽기 전에 형식을 확인합니다. 업데이트·변환은 토큰을 실은 POST로만 실행합니다(adm/browscap*.php, plugin/browscap/).
- **KVE-2026-3251 에디터 이미지 업로드:** 비회원 업로드 허용 여부, 파일당 크기, 세션·회원별 누적 개수·용량 제한을 추가했습니다(새 파일 lib/editor_upload.lib.php, extend/editor_upload.extend.php).
- **상품코드 결함:** 상품 엑셀 일괄등록은 값 전체가 지수 표기(예: `1.23457E+11`)인 상품코드만 숫자로 바꿉니다(adm/shop_admin/admin.shop.lib.php).
- PHP 8.3·8.4·8.5 문법 검사와 단위·회귀 검사를 통과했습니다. 새로 설치한 사이트에서 각 문제의 거부·정상 동작을 HTTP 검사와 브라우저로 확인했고, 이니시스 간편인증·KCP 본인확인·카카오·구글 로그인·Browscap 업데이트는 실제 연동으로 확인했습니다. 변경 코드에 PHP 5.2보다 새 구문·함수가 없는지 정적으로 검사했습니다.

**[릴리즈 노트 및 업데이트 안내]**

- 버전: 5.6.55
- 배포일: 2026-11-23
- 패치 기준: 5.6.54
- DB업그레이드: 불필요 (새 DB 변경 없음)
- 삭제 대상 파일: 없음

1. 파일과 DB를 백업하고 업데이트 중 사이트 이용을 일시 중지합니다.
2. 5.6.54 사용자는 패치 ZIP을 적용합니다. 2026-11-17에 잠시 공개되었던 이전 5.6.55를 적용했던 사이트는 패치 ZIP 대신 전체 배포본을 기준으로 사용자 수정 사항을 병합합니다. 그 밖의 이전 버전도 전체 배포본을 기준으로 병합하고, 기존 data와 DB 설정을 보존합니다.
3. 이번 버전에서 확인할 사항입니다.
   - **부관리자:** 그룹 관리자 지정·그룹 삭제는 최고관리자만 합니다. 회원관리·투표·회원메일·추가배송비·인기검색어·SMS5에서 삭제가 필요한 부관리자에게는 `d` 권한을 줍니다. 그룹·게시판·분류별 관리자와 접근 설정이 의도대로인지 점검합니다.
   - **직접 만든 스킨·테마:** 회원정보 수정 폼(`register_form.skin.php`)에는 `member_update_token` 숨은 필드가, 스크랩·위시리스트·마이페이지·배송지 삭제 링크에는 `del_post()`/`g5_post_href()` 호출이 필요합니다. 상품명·배송 정보를 출력하는 스킨은 `get_text()`를 적용합니다(두 번 적용하지 않음). 기본·basic 테마를 참고합니다.
   - **기존 방식 KCP 본인확인:** api_v2 전환을 권장합니다. 인증 창을 10분 넘게 두면 다시 인증해야 합니다. 운영 사이트에서 테스트 모드를 쓰지 않는지 확인합니다.
   - **서버 인증서 저장소:** 서버가 외부 HTTPS 인증서를 확인할 수 있어야 현금영수증·간편인증·소셜 로그인·네이버페이·이니시스 승인 통신이 됩니다. 실패하면 PHP의 `curl.cainfo`·`openssl.cafile` 설정을 확인하거나 `extend/`에 `define('G5_TLS_CA_FILE', '/경로/cacert.pem');`을 지정합니다.
   - **소셜 로그인:** 서버 통신이 노출되었을 가능성이 있으면 각 제공자의 Client Secret을 교체하고, 관리자 계정의 소셜 연결을 점검합니다.
   - **현금영수증(KCP 외):** PG 관리자의 발급 내역과 주문을 대조합니다. "처리 확인 필요"로 표시된 주문은 PG 내역과 대조해 정리합니다. `shop/<PG>/taxsave_form.php`를 직접 고쳤다면 `cash_token` 필드를 넣습니다.
   - **엑셀 업로드:** xls·xlsx만 받습니다. 확장자만 `.xls`인 HTML·CSV 파일 등은 Excel에서 xls·xlsx로 다시 저장합니다. 10MiB·10,000행을 넘는 파일은 나눠 올립니다. 상품 엑셀 업로드 화면을 직접 고쳤다면 `token` 필드를 넣습니다.
   - **Browscap:** Browscap을 쓰면 관리자 화면에서 업데이트를 다시 실행합니다. 이전 캐시는 읽지 않습니다.
   - **에디터 업로드:** 비회원은 에디터로 이미지를 올릴 수 없습니다. 계속 허용하려면 `extend/editor_upload.extend.php`의 `G5_EDITOR_UPLOAD_GUEST`를 `true`로 바꿉니다.
   - **기존 데이터:** 패치 전에 엑셀로 넣은 상품명·배송 정보에 태그가 남아 있을 수 있습니다. 상품을 다시 저장하면 정리됩니다. 태그로 꾸민 상품명은 태그 문자열로 보이므로 다시 저장합니다.
4. 이전 버전에서 미완료한 DB 업그레이드가 있다면 관리자 DB 업그레이드에서 완료합니다.
5. PHP 코드 캐시와 CDN·페이지 캐시를 사용한다면 갱신합니다(특히 `js/common.js`, `js/autosave.js`). 다음을 확인한 뒤 서비스를 재개합니다. 문제가 생기면 함께 백업한 이전 코드로 복원합니다.
   - 로그인·회원가입·회원정보 수정, 스크랩·위시리스트·배송지 삭제
   - 부관리자 계정의 게시판그룹·게시판·분류 관리
   - 사용하는 본인확인·소셜 로그인·현금영수증
   - 상품·배송 엑셀 업로드, 주문내역 CSV

## 검증 범위

PHP 8.3·8.4의 신규 설치본에서 KVE별 단위·HTTP 회귀 검사를 실행했고, 수정 전 코드에서는 해당 검사가 실패함을 확인했습니다. 7개 조치를 합친 코드로도 같은 검사를 반복했습니다.

웹 설치 화면으로 새로 설치한 사이트에서 다음을 브라우저로 확인했습니다.

- 이동 주소 거부, 회원정보 수정, 위임 관리자의 그룹·게시판 거부와 본인 범위 처리, 삭제 권한·POST 삭제
- 상품·배송 엑셀 업로드와 화면 출력, 주문내역 CSV, 에디터 업로드
- 실제 연동: 이니시스 간편인증(테스트 상점), 기존 방식 KCP 본인확인(테스트 모드), 카카오·구글 로그인, Browscap 업데이트. 위조한 응답·콜백은 거부되었습니다.

하위 PHP 버전은 변경 코드에 PHP 5.2보다 새 구문·함수가 없는지 정적으로 검사했습니다.

실제 현금영수증 발급(PG 대역으로 검사), 네이버 로그인, 실제 배송 안내 메일 발송, PHP 8.3 미만 실제 실행은 이번 검증 범위에 포함하지 않았습니다.
