# 첨부파일 저장 파일명의 IP 파생값 제거

## 변경 범위

게시판 및 1:1 문의에서 신규 업로드하거나 교체하는 첨부파일은 `32자리 16진수 난수.확장자`로 저장한다. 파일명에 IP, 세션, 시각 및 그 해시를 넣지 않는다. 원본 파일명은 기존처럼 `bf_source`, `qa_source1`, `qa_source2`에 보관하여 다운로드에 사용한다. 기존 확장자 실행 방지와 업로드 검사는 유지한다.

난수는 업로드마다 16바이트를 새로 생성한다. `random_bytes()`를 우선 사용하고, 해당 API가 없는 환경에서는 `openssl_random_pseudo_bytes()`의 강한 난수 여부를 확인한다. 두 API가 없는 Unix 환경에서는 `/dev/urandom`을 읽는다. PHP 5.2에서도 해석할 수 있는 문법을 사용하며, 안전한 난수 소스가 없는 환경에서는 첨부 업로드를 실패 처리한다. Windows의 구형 PHP 환경은 OpenSSL 난수 API 또는 PHP 업그레이드가 필요할 수 있다.

선택된 난수 API의 실패, 약한 난수 응답, 길이 부족은 업로드 실패로 처리한다. 시각, IP, `shuffle()` 등으로 대체하지 않는다. 파일 경로를 배타적으로 확보하고 충돌하면 새 난수로 최대 10회 시도한다. 파일 이동이 실패하면 확보한 빈 파일을 제거한다. 교체 업로드 실패 시 기존 파일과 DB 참조를 보존하고 실패 안내를 표시한다. 삭제 체크와 교체 업로드를 함께 보낸 경우에도 새 파일 저장 성공 후 기존 파일을 삭제한다. 게시글 전체 저장을 롤백하는 변경은 아니므로 본문이나 다른 첨부파일은 저장될 수 있다.

기존 저장 파일명을 읽는 이미지·썸네일·다운로드 경로와 DB 스키마는 변경하지 않는다. CAPTCHA, 에디터 등 다른 업로드 경로 및 외부 플러그인의 자체 파일명 생성은 이번 변경 범위에 포함하지 않는다.

## 기존 파일에 남는 노출과 선택적 이전

이번 변경은 기존 파일명을 자동으로 바꾸지 않는다. 기존 URL에는 IP 파생 접두사가 남아 있으며, 이미 외부에 복사된 URL이나 캐시까지 회수할 수 있다고 보장하지 않는다.

기존 파일 이전이 필요한 운영자는 다음 순서로 별도 유지보수 작업을 준비한다. 아래는 이전 절차이며 자동 이전 스크립트는 제공하지 않는다.

1. DB, 첨부파일, 썸네일과 외부 스토리지를 백업하고 업로드·수정·삭제를 일시 중지한다. 복구 가능한 시험 환경에서 먼저 검증한다.
2. 게시판의 `bf_file`과 1:1 문의의 `qa_file1`, `qa_file2`를 기준으로 실제 파일 목록을 수집한다. 플러그인의 `bf_fileurl`, `bf_thumburl`, `bf_storage` 및 외부 스토리지 참조도 조사한다.
3. 각 파일에 독립적인 안전한 난수 이름을 배정하고 기존 경로→새 경로 대응표를 비공개로 보관한다. 원본 다운로드 이름은 유지하며, 충돌·누락·중복 참조를 확인한다.
4. 새 경로에 파일을 복사한 다음 DB 파일 참조와 게시글·문의 본문·사용자 정의 스킨 등에 저장된 직접 링크를 대응표로 변경한다. 단순한 일괄 문자열 치환으로 다른 링크를 손상시키지 않도록 한다.
5. 기존 이름 기반 썸네일은 삭제 후 재생성하고 페이지 캐시·CDN·외부 스토리지 캐시를 무효화한다. 이미지 표시, 다운로드 내용과 원본 이름, 교체, 삭제 및 권한 검사를 확인한다.
6. 검증 후 기존 공개 경로를 제거한다. 기존 URL을 새 URL로 리다이렉트하면 IP 파생 URL과 새 파일의 연결이 남으므로 노출 제거 목적에 맞는지 판단한다. 링크 단절 가능성을 운영 정책에 반영한다.
7. 실패 시 대응표와 백업을 사용해 파일 및 DB 참조를 함께 복구한다. 대응표와 백업은 공개 웹 경로 밖에 보관하고 보관 기간에 따라 폐기한다.

## 검증

`php tests/attachment.php`는 PHP 7 이상 CLI에서 DB 없이 실행한다. 실제 OS 난수 반복 생성과 함께 난수 예외·길이 부족·약한 응답·소스 부재, 충돌 재시도와 상한, 이동 실패 정리, 확장자 보존·실행 방지, 두 업로드 루프의 교체 실패·성공·삭제 및 원본 이름 보존을 검증한다. 오류 경로는 테스트 namespace의 대체 함수로 재현한다.

배포 환경에서는 게시판과 1:1 문의 각각에서 이미지 및 일반 파일의 신규 첨부, 이미지 표시·썸네일 생성, 다운로드 원본 이름, 교체·삭제를 점검한다. 이전 버전에서 올린 첨부파일도 같은 항목으로 점검한다. PHP 5.2 등 구형 런타임과 플러그인·외부 스토리지 조합은 해당 환경에서 별도로 확인해야 한다.
