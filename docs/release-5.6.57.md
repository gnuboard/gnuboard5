# 그누보드 5.6.57 비밀번호 찾기 요청 제한 저장소 호환성 및 PHP 최소 버전 안내

InnoDB를 쓸 수 없는 DB 서버에서 비밀번호 찾기가 막히고 관리자 화면에 경고가 계속 표시되던 문제를 수정했습니다. PHP 7.0 미만 서버에서는 구문 오류 대신 최소 버전 안내가 표시되도록 했고, 설치 화면의 PHP 확장 점검을 README 요구사항과 맞췄습니다. 새 DB 변경과 삭제 대상 파일은 없으며, 5.6.56 사용자는 패치 파일을 적용할 수 있습니다.

## 개발자 노트

비밀번호 찾기 요청 횟수 제한은 `g5_abuse_rate` 테이블을 사용합니다. 그동안은 여러 한도를 한 번에 확보하기 위해 이 테이블이 InnoDB여야 했습니다.

그런데 InnoDB를 쓸 수 없는 DB 서버에서는 설치나 DB 업그레이드 때 `ENGINE=InnoDB` 지정이 경고만 남기고 MyISAM으로 대체됩니다. 설치와 DB 업그레이드는 성공으로 끝나지만, 이 테이블을 사용할 수 없다고 판단해 비밀번호 찾기가 처음부터 막혔습니다. 최고관리자 화면의 모든 관리자 페이지에는 "비밀번호 찾기 요청 제한 저장소를 확인할 수 없습니다" 경고가 표시됐습니다. 경고가 안내하는 DB 업그레이드 화면에는 모든 항목이 적용됨으로 나와, 운영자가 할 수 있는 조치가 없었습니다.

이번 버전부터 MyISAM(또는 Aria)으로 만들어진 테이블에서도 비밀번호 찾기가 동작합니다. 이 경우 트랜잭션 대신 DB 이름 잠금(`GET_LOCK`)으로 요청을 하나씩 처리하고, 한도를 하나라도 확보하지 못하면 앞서 확보한 한도를 되돌립니다. InnoDB 테이블은 지금처럼 트랜잭션으로 처리합니다. 이미 MyISAM으로 만들어진 사이트는 코드만 업데이트하면 경고가 사라지며, DB를 따로 바꿀 필요는 없습니다.

테이블이 없거나 구조가 다른 등 실제로 사용할 수 없는 상태라면, 관리자 경고에 원인이 한 줄로 표시됩니다. DB 업그레이드 화면의 "비밀번호 찾기 요청 제한 저장소 점검"에서는 저장 엔진, 동작 방식, DB 서버의 InnoDB 지원 여부, 컬럼 구조와 조치 방법을 확인할 수 있습니다. DB 동시 접속 수 제한으로 연결하지 못한 경우도 따로 안내합니다.

그누보드 5.6.45부터는 PHP 7.0 문법을 사용합니다. 하지만 실행 시 버전 검사는 PHP 5.2.17 기준이어서, PHP 5 서버에서는 안내 대신 `syntax error, unexpected '?'` 같은 구문 오류가 났습니다. 이제 PHP 7.0 미만이면 사이트와 설치 화면 모두에서 "PHP 7.0 or higher required" 안내를 표시합니다.

설치 첫 화면의 서버 환경 점검도 README의 요구사항과 같아졌습니다. iconv와 GD는 회원가입과 자동등록방지 문자 등에서 필요하므로 필수로 바뀌었습니다. 이 두 확장이 없는 서버에서는 신규 설치를 진행할 수 없습니다.

## 패치 노트

- **요청 제한 저장소:** MyISAM·Aria 저장소에서 이름 잠금으로 한도 확보를 처리합니다. 하나라도 확보하지 못하면 앞서 확보한 한도를 확보 직전 값으로 되돌립니다. 지원하지 않는 다른 엔진은 지금처럼 거부합니다(lib/abuse_rate.lib.php).
- **저장소 점검:** 저장소를 사용할 수 없는 원인을 연결·테이블·구조·저장 엔진별로 구분합니다(lib/abuse_rate.lib.php).
  - DB 업그레이드 화면에 저장소 점검 영역을 추가했습니다(adm/dbupgrade.php).
  - 관리자 상단 경고에 원인과 점검 영역 링크를 표시합니다. MyISAM으로 정상 동작하면 경고하지 않습니다(adm/admin.head.php).
  - DB 오류 원문은 화면에 표시하지 않습니다.
- **설치 완료 화면:** 저장소가 MyISAM·Aria로 만들어지면 동작 방식을 안내합니다(install/install_db.php).
- **PHP 최소 버전 검사:** 사이트(common.php)와 설치 화면(install/install_common.php)의 실행 시 최소 버전 검사를 PHP 7.0으로 올렸습니다.
- **설치 환경 점검:**
  - 필수: MySQL 확장, JSON, iconv, GD
  - 권장: mbstring, OpenSSL, cURL
  - 쓰이지 않는 Fileinfo 항목은 뺐습니다(install/library.check.php).
- **README:** 요구사항(PHP 7.0 이상, PHP 확장 표), 설치, 업데이트 안내를 정리했습니다. 이 내용은 5.6.56 배포 후 공개 저장소에 먼저 반영됐습니다.

**[릴리즈 노트 및 업데이트 안내]**

- 버전: 5.6.57
- 배포일: 2026-11-26
- 패치 기준: 5.6.56
- DB업그레이드: 불필요 (새 DB 변경 없음)
- 삭제 대상 파일: 없음

1. 파일과 DB를 백업하고 업데이트 중 사이트 이용을 일시 중지합니다.
2. 5.6.56 사용자는 패치 ZIP을 적용합니다. 이전 버전은 전체 배포본을 기준으로 사용자 수정 사항을 병합하고, 기존 data와 DB 설정을 보존합니다. 5.6.51의 삭제 대상 파일 안내도 함께 확인합니다.
3. 관리자 화면에 "비밀번호 찾기 요청 제한 저장소를 확인할 수 없습니다" 경고가 있었다면, 업데이트 후 사라졌는지 확인합니다. 경고가 남아 있으면 관리자 DB 업그레이드 화면의 저장소 점검에 표시된 원인과 조치 방법을 확인합니다.
4. PHP 7.0 미만 서버는 이 버전을 실행할 수 없으므로 PHP를 먼저 올립니다(PHP 8.3 이상 권장).
5. 이전 버전에서 미완료한 DB 업그레이드가 있다면 관리자 DB 업그레이드에서 완료합니다.
6. PHP 코드 캐시와 별도 CDN·페이지 캐시를 사용한다면 갱신합니다. 비밀번호 찾기 메일 요청과 관리자 화면을 확인한 뒤 서비스를 재개합니다. 문제가 생기면 함께 백업한 이전 코드로 복원합니다.

## 검증 범위

PHP 8.4 신규 설치본에서 저장소를 InnoDB·MyISAM으로 각각 두고 비밀번호 찾기 요청 제한을 검사했습니다. InnoDB를 끈 MariaDB 서버에도 새로 설치해 같은 검사를 했습니다. 동시 요청에서 메일이 한 번만 발송되는지, 두 번째 한도 확보가 실패하면 첫 한도가 되돌려지는지, 잠금 대기를 2초에서 중단하는지, 구조 오류를 원인과 함께 안내하는지 확인했습니다.

InnoDB를 끈 서버에서는 브라우저로 웹 설치, 관리자 화면, 비밀번호 찾기 메일 요청, 재설정 링크와 새 비밀번호 로그인도 확인했습니다.

PHP 최소 버전 검사는 버전 검사 전에 해석되는 파일에 PHP 5.2에서 해석되지 않는 구문이 없는지 정적으로 검사했습니다. 변경 코드에 PHP 7.0보다 새 구문·함수가 없는지도 정적으로 검사했습니다. 설치 환경 점검은 PHP 8.3·8.4와 확장을 끈 PHP 8.4에서 확인했습니다.

PHP 5·7 실제 실행, MySQL 5.0 실서버, Aria 기본 엔진 서버는 이번 검증 범위에 포함하지 않았습니다.
