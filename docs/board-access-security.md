# 게시판 비밀글 인증 및 처리 경로 접근통제

답글·댓글·스크랩 댓글 저장과 링크·다운로드는 화면 접근 여부와 관계없이 현재 게시판 및 게시물 권한을 검사한다. 공통 판정은 `lib/board_access.lib.php`에서 수행하며 `lib/common.lib.php`가 로드한다.

## 인증 범위

- 비밀글 인증은 `ss_secret_v2_{게시판}_{게시물 ID}`에 저장한다. 댓글과 답글의 인증으로 원글 또는 다른 답글을 인증하지 않는다.
- 인증값은 게시물 유형·스레드·부모·작성자·작성 시각·공개 설정·비밀번호와 현재 로그인 계정에 연결된다. 회원 비밀번호를 대신 확인하는 게시물은 회원 비밀번호 변경도 반영한다.
- 기존 `ss_secret_{게시판}_{wr_num}` 및 `ss_secret_comment_*`는 더 이상 읽지 않는다. 패치 적용 후 기존 비밀번호 인증은 다시 받아야 하며 로그인 세션을 일괄 삭제할 필요는 없다.
- 회원 원 작성자는 기존과 같이 자신의 스레드에 있는 관리자 답글을 읽을 수 있다. 비밀번호로 인증한 원글의 권한은 같은 비밀번호를 상속한 답글로만 전달된다. 답글에서 원글로는 전달되지 않는다.
- `password_check.php`의 `s`는 비밀 게시물, `sc`는 비밀 댓글만 허용한다. 댓글 인증 전에 부모 게시물 접근을 검사한다. 구버전 MySQL 비밀번호 형식도 동일한 대상별 인증을 사용한다.
- `ss_view_*`는 조회수/다운로드 흐름용 표식이며 현재 비밀글 권한의 증명이 아니다. 링크 및 다운로드는 현재 권한을 다시 검사한다.

## 쓰기 정책

- 신규 글·수정·답글은 그룹 가입 및 본인/성인확인 조건을 저장 단계에서도 확인한다.
- 답글은 읽기 권한과 기존 답변 권한을 함께 검사한다. 회원 비밀글은 작성자/관리자만 답변할 수 있고 비회원 비밀글은 관리자만 답변할 수 있다.
- 댓글·스크랩 댓글은 원글 읽기 및 비밀 인증을 확인한다. 댓글 수정 대상은 실제 댓글이어야 하며 요청의 부모 게시물에 속해야 한다.
- 그룹 접근에서 기존 읽기 정책은 최고/그룹 관리자에게, 쓰기 정책은 최고/그룹/게시판 관리자에게 예외를 적용한다. 답글·댓글 등 원글 열람이 필요한 작업에는 읽기 정책도 적용된다.

## 검증

```text
php tests/board_access.php
python3 tests/board_access_http.py
```

첫 테스트는 DB 없이 인증 범위와 권한 조합을 확인한다. 두 번째는 Linux에서 `php`, `mariadb`, `mariadbd`, `mariadb-install-db`를 이용해 `/tmp/g5-board-access-*`에 새 설치·전용 DB·루프백 웹 서버를 만든다. 운영 설정을 읽지 않으며 테스트 종료 시 두 서버를 종료한다. 합성 DB, 로그 및 결과는 출력한 임시 경로에 남긴다.

HTTP 테스트는 제품의 실제 로그인, 토큰, 처리 파일과 MariaDB를 사용한다. 테스트 사본의 `audit_fixture.php`는 CAPTCHA 정답, 등록 간격 초기화, 구버전 세션 주입 및 인증 세션 관찰만 제공하며 제품 권한 함수나 SQL을 대체하지 않는다. 이 fixture는 테스트 실행 중 임시 사본에만 생성된다.

PHP 8.4.27 / MariaDB에서 권한 테스트 38개, HTTP·DB 테스트 87개를 통과했다. 정상 회원/비회원·세 관리자 역할·공개/선택 비밀/강제 비밀·답글 수정·비밀번호 변경·구버전 비밀번호·그룹/인증 제한·PC/모바일 응답·정상 첨부 다운로드를 포함한다. HTTP 서버 로그의 PHP 경고/오류도 검사한다. 브라우저 JavaScript 자동화나 사용자 지정 스킨별 검증은 포함하지 않는다.

## 반영 시 유의점

새 공통 라이브러리, 이를 로드하는 공통 파일, 변경한 게시판 처리 파일과 구버전 호환 확장을 함께 반영해야 한다. 사용자 지정 스킨/플러그인이 구 세션 키를 직접 검사한다면 새 공통 판정으로 전환해야 한다.

정적 이미지·첨부 URL 자체의 웹 서버 접근통제 및 모든 배포 버전의 영향 범위는 이 패치로 확정하지 않는다. 이번 변경은 PHP 게시판 처리 경로의 권한 검사를 보강하며 정적 파일 제공 방식을 변경하지 않는다.
