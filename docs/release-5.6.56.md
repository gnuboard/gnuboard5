# 그누보드 5.6.56 상품 옵션 목록 화면 수정 안내

관리자 상품 등록·수정 화면에서 옵션목록생성으로 만든 입력칸의 id가 겹치던 문제를 수정했습니다. 새 DB 변경과 삭제 대상 파일은 없으며, 5.6.55 사용자는 패치 파일을 적용할 수 있습니다.

## 개발자 노트

쇼핑몰 관리자의 상품 등록·수정 화면에서 선택옵션(예: 색상·크기)이나 추가옵션 항목을 입력하고 옵션목록생성을 누르면 옵션 조합마다 추가금액·재고수량 입력칸이 만들어집니다.

그런데 이 입력칸의 id를 옵션1 순번으로만 만들어, 옵션2·옵션3 조합 행끼리 같은 id가 여러 번 생겼습니다. 추가옵션도 같은 항목 안의 행끼리 id가 겹쳤습니다. 같은 id가 여러 개 있으면 화면의 이름표(label)가 엉뚱한 입력칸을 가리키고, 화면 낭독기 사용자나 id로 입력칸을 찾는 사이트 맞춤 스크립트가 다른 행을 다룰 수 있습니다. 기존 옵션 행의 재고수량 입력칸 id 오타와 추가옵션 전체선택 체크박스의 id 누락으로 이름표가 연결되지 않던 문제도 함께 있었습니다.

이번 버전부터는 생성되는 행마다 고유한 id를 쓰고, 이름표가 각 행의 입력칸과 정확히 연결됩니다. 저장에 쓰는 입력값 이름과 옵션 데이터는 바뀌지 않으므로, 이전 버전에서 등록한 상품의 옵션도 그대로 수정·저장할 수 있습니다.

## 패치 노트

- **선택옵션 목록:** 옵션목록생성으로 만드는 행의 입력칸 id를 행마다 증가하는 번호로 만들어 중복을 없앴습니다. 기존 옵션 행의 재고수량 입력칸 id 오타(`op_stock_qty_`)를 고쳐 이름표와 연결했습니다(adm/shop_admin/itemoption.php).
- **추가옵션 목록:** 옵션목록생성으로 만드는 행의 입력칸 id를 행마다 증가하는 번호로 만들었고, 전체선택 체크박스에 이름표가 가리키는 id를 붙였습니다(adm/shop_admin/itemsupply.php).
- 폼 입력값 이름(`opt_id[]`, `opt_price[]` 등)과 옵션 ID는 바꾸지 않았습니다. 기본 관리자 스크립트는 이 id를 사용하지 않습니다.
- 이번 변경에 새 PHP 버전 전용 구문이나 함수는 추가하지 않았습니다.

1. 파일과 DB를 백업하고 업데이트 중 사이트 이용을 일시 중지합니다.
2. 5.6.55 사용자는 패치 ZIP을 적용합니다. 이전 버전은 전체 배포본을 기준으로 사용자 수정 사항을 병합하고, 기존 data와 DB 설정을 보존합니다. 5.6.51의 삭제 대상 파일 안내도 함께 확인합니다.
3. 관리자 상품 화면에 직접 넣은 스크립트가 `#opt_price_0`처럼 옵션 입력칸 id를 참조한다면, 행 번호가 행마다 달라졌으므로 해당 스크립트를 확인합니다. 기본 스킨만 쓰는 사이트는 따로 할 일이 없습니다.
4. 이전 버전에서 미완료한 DB 업그레이드가 있다면 관리자 DB 업그레이드에서 완료합니다.
5. PHP 코드 캐시와 별도 CDN·페이지 캐시를 사용한다면 갱신합니다. 상품 등록·수정 화면에서 옵션목록생성과 저장을 확인한 뒤 서비스를 재개합니다. 문제가 생기면 함께 백업한 이전 코드로 복원합니다.

## 검증 범위

PHP 8.4 신규 설치본(엄격 모드 MariaDB)에서 선택옵션 12행(3×2×2)과 추가옵션 5행을 생성해, 겹치는 id가 각각 15종·10종에서 0으로 줄고 입력값 이름과 값이 수정 전과 같음을 확인했습니다.

이전 방식으로 저장된 옵션 상품의 수정 화면과 수정 중 옵션 재생성에서 저장된 값이 유지되는 것을 확인했습니다. 브라우저에서 옵션목록생성·전체선택·일괄적용·선택삭제·이름표 클릭과, 새 상품 저장 및 기존 상품 재저장 후 옵션 값을 확인했습니다. 하위 PHP 버전은 변경 코드에 PHP 5.2보다 새 구문·함수가 없는지 정적으로 검사했습니다.

사이트별로 추가한 관리자 스크립트와 PHP 8.3 미만 실제 실행은 이번 검증 범위에 포함하지 않았습니다.
