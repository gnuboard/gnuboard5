# 그누보드 5.6.54 결제 취소 처리 수정 안내

쇼핑몰 주문 처리 중 PG 결제 승인 뒤 오류가 나면 결제를 취소해야 하는데, 취소가 실행되지 않던 문제를 수정했습니다. 새 DB 변경과 삭제 대상 파일은 없으며, 5.6.53 사용자는 패치 파일을 적용할 수 있습니다.

## 개발자 노트

쇼핑몰에서 고객이 카드 등으로 결제를 마친 뒤 주문을 저장하는 단계에서 문제가 생기면, 그누보드는 PG 결제를 취소하고 주문을 되돌려야 합니다. 결제금액이 주문금액과 다르거나, 주문 저장에 실패하거나, 동시에 주문해 포인트 잔액이 모자라거나, 같은 쿠폰을 두 번 쓰려는 경우가 여기에 해당합니다.

그런데 5.6.26부터 이 결제 취소를 담당하는 공통 처리 파일이 실행되는 즉시 종료되도록 잘못 작성되어 있었습니다. 파일 첫머리의 접근 확인에 어디에서도 정의되지 않는 값을 쓴 것이 원인입니다. 그 결과 위 상황에서 결제가 취소되지 않았고, 주문 삭제·장바구니 복구·관리자 알림 같은 뒤따르는 처리도 이루어지지 않은 채 화면이 비어 있는 상태로 끝났습니다.

특히 쿠폰 이중사용을 막는 처리에서는 쿠폰 사용 기록만 지워지고 결제된 주문은 그대로 남아, 같은 쿠폰을 다시 쓸 수 있었습니다.

이번 버전부터는 결제 취소가 정상적으로 실행되고, 이어서 주문 삭제·장바구니 복구·포인트 원복과 안내 화면 표시가 원래대로 이루어집니다. 개인결제에서 결제정보 저장에 실패한 경우에도 토스페이먼츠 결제가 올바르게 취소됩니다.

## 패치 노트

- **결제 취소 공통 처리:** shop/cancel_pg.inc.php의 접근 확인을 공통 초기화 상수로 바꿔, 주문서 처리에서 불러올 때 PG별 결제 취소가 실행되도록 했습니다. 파일을 직접 요청하면 기존처럼 아무것도 실행하지 않습니다.
  - 대상: PC·모바일 주문서 처리(shop/orderformupdate.php, mobile/shop/orderformupdate.php)의 결제금액 불일치, 주문정보 입력 오류, 주문상태 변경 오류, 포인트 잔액 부족, 쿠폰 이중사용
- **개인결제 토스 취소:** PC 개인결제 처리(shop/personalpayformupdate.php)에서 결제정보 저장에 실패했을 때 토스페이먼츠 결제를 토스 취소로 처리합니다. 모바일은 이미 같은 처리를 하고 있었습니다.
- **문서:** 마이그레이션 디렉터리 차단 안내(docs/migration-directory-security.md)의 nginx 하위 경로 예시를 일반 예시(`/gnuboard5/`)로 바꿨습니다.
- 이번 변경에 새 PHP 버전 전용 구문이나 함수는 추가하지 않았습니다.

1. 파일과 DB를 백업하고 업데이트 중 사이트 이용을 일시 중지합니다.
2. 5.6.53 사용자는 패치 ZIP을 적용합니다. 이전 버전은 전체 배포본을 기준으로 사용자 수정 사항을 병합하고, 기존 data와 DB 설정을 보존합니다. 5.6.51의 삭제 대상 파일 안내도 함께 확인합니다.
3. 5.6.26 이후 버전을 운영하며 결제 대행(PG)을 사용했다면, PG 관리자 화면의 승인 내역과 쇼핑몰 주문 내역을 대조해 주문 없이 승인만 남은 결제가 있는지 확인합니다. 있다면 PG 관리자 화면에서 직접 취소하거나 고객에게 안내합니다. 같은 쿠폰이 여러 주문에 쓰였는지도 쿠폰 사용 내역에서 확인하기를 권장합니다.
4. 이전 버전에서 미완료한 DB 업그레이드가 있다면 관리자 DB 업그레이드에서 완료합니다.
5. PHP 코드 캐시와 별도 CDN·페이지 캐시를 사용한다면 갱신합니다. 주문서 작성·결제와 개인결제 화면을 확인한 뒤 서비스를 재개합니다. 문제가 생기면 함께 백업한 이전 코드로 복원합니다.

## 검증 범위

PHP 8.3·8.4·8.5에서 결제 취소 공통 처리를 PG 5종(KCP, LG U+, 토스페이먼츠, KG이니시스, NICEPAY)과 기본값별로 불러, 해당 PG의 취소 처리가 실행되고 주문서 처리로 돌아오는지 검사했습니다. 개인결제 처리의 PG별 취소 분기에 토스페이먼츠 처리가 있는지도 검사했습니다. 수정 전 코드에서는 검사 도중 종료되어 문제가 재현되었습니다.

PHP 8.3·8.4의 신규 설치본에서 결제 취소 공통 처리 파일을 직접 요청하면 아무것도 실행되지 않고, 주요 화면이 경고 없이 열리는 것을 확인했습니다. 하위 PHP 버전은 변경 코드에 PHP 5.2보다 새 구문·함수가 없는지 정적으로 검사했습니다.

실제 PG 결제 승인·취소 호출, PHP 8.3 미만 실제 실행, 외부 커스텀 주문서 스킨은 이번 검증 범위에 포함하지 않았습니다.
